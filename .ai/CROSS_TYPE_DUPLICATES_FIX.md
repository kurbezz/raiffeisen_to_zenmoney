# Исправление кросс-типных дубликатов операций

## Проблема

Одна и та же операция банка могла импортироваться дважды в ZenMoney как разные типы операций:

**Пример с 14 февраля 2026:**
- **Операция 1:** SMS из банка - "Пополнение на счет" - 97566 RSD (добавляется автоматически через интеграцию Raiffeisen-ZenMoney)
- **Операция 2:** Из выписки XML - "Обмен валют: -97566 RSD → +97566 RSD" (добавляется через скрипт)

**Как это происходит:**

1. **Этап 1:** Приходит SMS уведомление от банка о платеже
   - Raiffeisen автоматически добавляет операцию в ZenMoney
   - Операция: SimplTransaction без специального комментария (может быть "Пополнение" или пусто)
   - Reference может отсутствовать в SMS

2. **Этап 2:** Приходит полная выписка (XML)
   - Скрипт парсит XML и видит две связанные операции:
     - -97566 RSD (с description "po kursu" - по курсу)
     - +97566 RSD  
   - Классифицирует как TransitionOperation (обмен валюты)
   - Добавляет в ZenMoney

**Результат:** Две операции в ZenMoney для одного платежа ❌

## Решение

Система двухуровневая:

### Уровень 1: Reference tracking (для выписок XML)

Все операции из XML выписок содержат банковский reference:

```python
@dataclass
class SimpleOperation:
    reference: str = ""

@dataclass
class TransitionOperation:
    from_reference: str = ""
    to_reference: str = ""
```

- Reference добавляется в комментарии для отслеживания
- Filter проверяет: если reference уже импортирована (как любой тип) → пропускает

### Уровень 2: Cross-type detection в auto-cleanup

Более надёжное решение - система автоматически **обнаруживает и удаляет** SMS операции, когда нашлась более полная версия из выписки:

```python
def find_duplicate_transactions():
    # Находит:
    # 1. SMS дубликаты (с/без "Stanje: ***")
    # 2. Import дубликаты (одна операция дважды из выписки)
    # 3. Cross-type дубликаты (SMS + Import с одинаковыми date/amount/currency)
    #    → Удаляет SMS версию, оставляет Import (более полную)
```

**Как это работает:**

```
SMS операция (из банка):
  - Дата: 2026-02-14
  - Сумма: 97566
  - Валюта: RSD
  - Комментарий: (пусто или "Пополнение")
  
+
  
Import операция (из выписки):
  - Дата: 2026-02-14
  - Сумма: 97566 (outcome)
  - Валюта: RSD (outcome)
  - Комментарий: "Обмен валют: -97566 RSD → +97566 RSD [Refs: ...]"

=

Система обнаруживает: одинаковые date/amount/currency
Решение: Удалить SMS, оставить Import (более детальную)
```

## Как это работает

### Сценарий: 97566 RSD из SMS + выписка

**Шаг 1: SMS добавляет операцию в ZenMoney (автоматически)**
```
ZenMoney:
  - Платеж 97566 RSD (Пополнение) - добавлен в 14:00
```

**Шаг 2: Запуск скрипта импорта выписки**
```
1. auto_cleanup_duplicates() запускается первым
   → Обнаруживает SMS операцию (comment не начинается с "Импорт:"/"Обмен валют:")
   → Ищет import операции с одной date/amount/currency
   → Находит: "Обмен валют: -97566 RSD → +97566 RSD [Refs: ...]"
   → УДАЛЯЕТ SMS версию (она менее полная)

2. Далее импортируются новые операции из выписки
   → TransitionOperation с reference добавляется
   → Filter пропускает (не является дубликатом существующей)
```

**Результат: Только 1 операция в ZenMoney** ✅

## Преимущества

✅ Работает для SMS операций без reference  
✅ Автоматическое удаление при каждом запуске  
✅ Сохраняет более полную версию (из выписки)  
✅ Не требует ручного вмешательства  
✅ Совместимо со старыми операциями  

## Когда срабатывает

1. **SMS от банка добавляет простую операцию**
2. **Выписка содержит более полную информацию** (обмен валют, details, и т.д.)
3. **При синхронизации:**
   - Система обнаруживает что date/amount/currency совпадают
   - Удаляет SMS версию
   - Добавляет правильную версию из выписки
