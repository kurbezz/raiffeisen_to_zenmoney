# SMS Дубликаты - Полное руководство

## 🔍 Что такое SMS дубликаты

SMS операции в ZenMoney часто импортируются дважды:
- Первый раз с полным именем получателя
- Второй раз с суффиксом "Stanje: ***" (это SMS уведомление от банка)

**Пример:**
```
1. MERCHANT_NAME_ABC 123456789 RS          - SMS дубликат (ранняя версия)
2. MERCHANT_NAME_ABC 123456789 RS Stanje:  - Финальная версия
```

Система добавляет обе версии, создавая дубликаты в ZenMoney.

## ✅ Решение

### Часть 1: Очистка существующих SMS дубликатов
Создан скрипт `cleanup_sms_duplicates.py` который:
1. Находит все SMS операции на счетах Raiffeisen
2. Нормализует имена получателей (удаляет "Stanje: ***")
3. Группирует операции по (дата, сумма, валюта, нормализованный payee)
4. Удаляет старые версии, сохраняет новые

### Часть 2: Предотвращение новых SMS дубликатов
Обновлена логика фильтрации в `src/services/operations/filter.py`:
1. Добавлена функция `_normalize_payee()` для нормализации имен
2. Отслеживание SMS операций с нормализованными payee
3. Проверка дубликатов перед импортом новых операций

## 🔧 Как работает система

### Нормализация Payee

Функция `_normalize_payee()` обрабатывает имена получателей:

```python
# До нормализации
"DELIVERY_SERVICE_1 123456789 RS Stanje: ***"
"SUBSCRIPTION_SERVICE_1 +123456789 US Stanje:"

# После нормализации
"delivery_service_1 123456789 rs"
"subscription_service_1 +123456789 us"
```

### Поиск дубликатов

Операции группируются по ключу:
```python
key = (дата, сумма, валюта, нормализованный_payee)

Пример:
("2025-11-25", 2982.54, "RSD", "delivery_service_1 123456789 rs")
```

### Выбор какую операцию сохранить

Для каждой группы дубликатов:
1. Сортируют по времени создания (`created`)
2. **Сохраняют:** самую новую (последнюю)
3. **Удаляют:** все старые версии

## 🛡️ Защита от новых SMS дубликатов

После обновления `filter.py`, новые операции при импорте проверяются на SMS дубликаты:

```python
# Проверка перед импортом новой операции
sms_key = (дата, сумма, валюта, нормализованный_customer)

if sms_key not in existing_sms_transactions:
    # Импортировать операцию
    filtered_operations.append(operation)
else:
    # Пропустить (уже есть SMS версия)
    continue
```

## ❓ FAQ

### Q: Какие операции считаются SMS?
**A:** Операции на счетах Raiffeisen БЕЗ комментариев вида:
- "Импорт: ..."
- "Обмен валют: ..."
- "Transfer from Deel: ..."
- "Снятие наличных: ..."

Все остальные - это SMS операции.

### Q: Почему операция добавляется дважды?
**A:** Потому что:
1. SMS уведомление приходит первым (неполная информация)
2. Выписка приходит позже (полная информация)
3. Обе добавляются в ZenMoney как отдельные операции

### Q: Какую версию дубликата вы удаляете?
**A:** Удаляем **СТАРУЮ** версию (по времени создания), сохраняем **НОВУЮ**.

Это потому что новая версия обычно более полная и содержит корректную информацию.

### Q: Это повредит моим данным?
**A:** Нет. Удаляются только полные дубликаты (одинаковая дата, сумма, валюта, payee). 

Если операции отличаются хоть чем-то - они не будут удалены.

### Q: Нужно ли запускать это регулярно?
**A:** 
- **После развертывания:** один раз (для очистки истории)
- **Периодически:** раз в месяц для проверки
- **Автоматически:** новые дубликаты предотвращаются фильтром

### Q: Что если я случайно удалил нужную операцию?
**A:** К сожалению, удаление нельзя отменить через API. Потребуется:
1. Использовать резервную копию ZenMoney (если есть)
2. Или повторно импортировать из выписки

Поэтому сначала запустите без флага `--auto-confirm` и проверьте список.

### Q: Как узнать сколько SMS дубликатов у меня?
**A:** Запустите:
```bash
uv run python cleanup_sms_duplicates.py
```

Вывод покажет количество найденных групп дубликатов.
