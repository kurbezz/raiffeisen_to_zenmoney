## Что было изменено

### Основное изменение
**Файл:** `src/services/operations/preparer.py`

**Что исправлено:**
1. Добавлена инициализация переменной `processed_operations`
2. Добавлена логика для обнаружения и комбинирования связанных операций в одной валюте
3. Операции с одинаковой суммой но противоположными знаками (дебет/кредит) теперь объединяются в одну

**Как это работает:**
- Когда две операции имеют одинаковую ссылку/номер
- И одинаковую валюту (оба RSD)
- И одинаковую абсолютную сумму
- Но противоположные знаки (минус и плюс)
- Тогда они объединяются и в ZenMoney попадает только одна операция (положительная)

### Примечание
Обмены валют (USD↔RSD) и другие типы операций остаются неизменены и работают как раньше.

### Если нашлись дубликаты в ZenMoney

#### Режим просмотра (безопасно)
```bash
uv run python src/find_duplicates.py
```

Вы увидите список всех найденных дубликатов:
```
🔍 Найдено 2 групп дубликатов:

Группа 1:
  📅 Дата: 2026-01-14
  💰 Сумма: 40.0 RSD
  📝 Комментарий: Импорт: Raiffeisen banka a.d. Beograd (RSD)
  🔢 Количество дубликатов: 2
  Транзакции:
    1. ID: 83dff132-... | Создана: 2026-01-15 03:00:14  ✅ СОХРАНИТЬ
    2. ID: 833c83cd-... | Создана: 2026-01-15 03:00:14  ❌ УДАЛИТЬ
```

#### Режим удаления (с подтверждением)
```bash
uv run python src/find_duplicates.py
```

Скрипт спросит:
```
⚠️  ВНИМАНИЕ! Это действие нельзя отменить!
Удалить дубликаты? (да/нет):
```

Введите `да` для удаления.

#### Режим автоматического удаления (без подтверждения)
```bash
uv run python src/find_duplicates.py --auto-confirm
```

или

```bash
uv run python src/find_duplicates.py -y
```

**Внимание:** Используйте только если уверены!

## FAQ

### Q: Почему две операции объединяются в одну?
**A:** Потому что банк отправляет две связанные операции (дебет и кредит) как часть одного перевода. Объединение их в одну транзакцию в ZenMoney дает правильное отображение.

### Q: Как понять связаны ли две операции?
**A:** Операции считаются связанными если:
- Они имеют одинаковый номер ссылки (reference), ИЛИ
- Номер ссылки одной операции содержится в описании другой

Пример: Две операции с номером "97715RSD" считаются связанными.

### Q: Что происходит с операциями разных валют?
**A:** Операции разных валют (USD↔RSD) обрабатываются как раньше и создают `TransitionOperation` (обмен валют). Они не затронуты этим исправлением.

### Q: Будут ли потеряны данные?
**A:** Нет. Исправление только предотвращает импорт дублей. Когда две операции объединяются, используется положительная операция (входящий платеж), что является правильным.

### Q: Как часто нужно запускать скрипт очистки?
**A:** 
- **Один раз при развертывании** - для очистки существующих дубликатов
- **Периодически** (раз в месяц) - для проверки на предмет новых дубликатов
- **После обновления** - если что-то изменилось в логике

### Q: Влияет ли это на Deel переводы?
**A:** Нет. Deel переводы обрабатываются отдельно и не затронуты этим исправлением.

### Q: Влияет ли это на снятие наличных?
**A:** Нет. Снятия наличных обрабатываются отдельно и не затронуты этим исправлением.

### Q: Что если операции имеют одинаковую сумму но разные знаки и НЕ связаны?
**A:** Они не будут объединены, потому что проверяется наличие общей ссылки/номера. Несвязанные операции остаются отдельными.

### Q: Почему тест важен?
**A:** Тест проверяет что:
- Связанные операции объединяются правильно
- Несвязанные операции остаются отдельными
- Обмены валют по-прежнему работают
- Нет регрессий в других типах операций

### Q: Могу ли я отключить это исправление?
**A:** Да, используя откат:
```bash
git checkout src/services/operations/preparer.py
```

Но это не рекомендуется, так как проблема вернется.

### Q: Нужно ли менять конфиг?
**A:** Нет. Никакие файлы конфигурации менять не нужно. Исправление работает автоматически.

### Q: Есть ли побочные эффекты?
**A:** Нет известных побочных эффектов. Исправление:
- ✅ Не влияет на другие типы операций
- ✅ Не требует изменения конфигурации
- ✅ Полностью обратно совместимо
- ✅ Не вводит новые зависимости
